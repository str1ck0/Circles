# Circles — Implementation Plan

Working document for the portfolio push. Updated 2026-09-07.

**Goal:** get Circles hosted publicly, free and without a credit card, as a portfolio piece
demonstrating a full-stack Rails app with real-time features.

**Non-goals:** rebuilding the stack. Chat is Action Cable over WebSockets, which rules out
serverless/edge hosts. Don't migrate to Next.js, don't swap Postgres for SQLite, don't
replace Devise. The app works; this is a polish-and-ship effort.

## Phase 2 — Deploy

The config is written and committed. What remains is account creation, which requires the
user — Claude cannot sign up for third-party services.

**Chosen stack** (all free tier, no card):

| Concern | Service | Env var |
|---|---|---|
| Web | Render (`render.yaml`, `plan: free`, region `frankfurt`) | — |
| Postgres | Neon | `DATABASE_URL` |
| Redis (Action Cable) | Upstash | `REDIS_URL` (`rediss://`) |
| Images | Cloudinary | `CLOUDINARY_URL` |
| Geocoding | Mapbox | `MAPBOX_API_KEY` |

**Sequence:**

1. Create Neon project → copy the pooled connection string.
2. Create Upstash Redis DB → copy the `rediss://` URL.
3. In Render: New → Blueprint, point at the repo. `render.yaml` defines the service and
   declares every `sync: false` var, so Render will prompt for each secret (including the
   existing `CLOUDINARY_URL` and `MAPBOX_API_KEY` from `.env`).
4. Deploy. `SECRET_KEY_BASE` is auto-generated by Render (`generateValue: true`).
5. **After the first deploy**, set `APP_HOST` to the assigned hostname (e.g.
   `circles.onrender.com`, no scheme) and redeploy.

**`APP_HOST` is the step that's easy to miss.** It feeds
`config.action_cable.allowed_request_origins`. Without it the site loads fine and chat
silently fails to connect — the most likely post-deploy bug, and it won't appear in logs as
an obvious error.

`bin/render-build.sh` handles install → precompile → `db:prepare` → seed-if-empty. The
seed guard (`Rails.application.load_seed if User.count.zero?`) means redeploys preserve
visitor-created content.

**Free-tier caveat worth knowing:** Render's free web services spin down when idle and take
~30s to wake. Acceptable for a portfolio link; mention it in the README so a cold first load
doesn't read as a broken app.

**Health check** is `/users/sign_in` — a route that renders without a session.

## Phase 3 — Correctness cleanup

Small, independent, each a self-contained PR. None block deploy.

**`UserEventsController#create`** — the `else` branch calls `format.html` outside any
`respond_to` block, so a save failure raises `NameError` instead of redirecting. Wrap it in
`respond_to` mirroring the success branch. Only reachable when the save fails, which is why
it survived the redux pass.

**`PaymentsController#create` integer division** — `payments.amount` is an integer column
and `payment.amount / (splittees.count + 1)` truncates, so a £10 bill across 3 people loses
the remainder and balances drift. Options: distribute the remainder to the payer, or migrate
`amount` and `user_events.balance` to store minor units and handle rounding explicitly. The
former is a one-line fix; the latter is correct but touches the schema and the views.

**Stale scaffold test** — `test/controllers/user_circles_controller_test.rb` references a
nonexistent `user_circles_create_url` helper and is the suite's only failure. Delete it or
write it properly. Leaving a red suite in a portfolio repo is a bad look.

## Phase 5 — Optional polish

Only if time allows; none of it is load-bearing for a portfolio.

- **Test coverage.** Everything under `test/` except three model files is an empty scaffold.
  The highest-value additions are `PaymentsController` (the split arithmetic is the most
  intricate logic in the app) and the chat channels.
- **Playlist deletion UI.** Playlists can be added but not removed; routes were trimmed to
  implemented actions only, so this needs a route, an action and a view control.
- **Circle/event mirror duplication.** The two hierarchies are near-identical
  (messages, channels, playlists, Stimulus controllers). A shared concern would cut real
  duplication — but it's refactoring for its own sake unless something new needs adding to
  both.

## Context worth not re-deriving

- **The mirror pattern.** Circles and events each have their own messages, channel,
  playlists and Stimulus subscription controller. Fixes on one side almost always need the
  twin on the other.
- **`balance` is on `user_events`, not `users`** — bill splitting is scoped per event, not a
  global wallet.
- **`Circle#owner` was added by later migration** and is `optional: true`; older code may
  conflate ownership with membership.
- **Chat works locally with no Redis** thanks to the `async` adapter, so "it works on my
  machine" tells you nothing about production. Production needs `REDIS_URL` + `APP_HOST`.
- **Routes are trimmed to implemented actions**, so missing URL helpers are usually
  intentional, not a bug.
- **Repo is `str1ck0/Circles`, default branch `master`.** Solo repo; PR-per-change was the
  chosen workflow as of PR #1.
